# Upgrade all components

## Goal

Upgrade the project component stack in a controlled way so the TypeScript full-stack scaffold stays current without breaking the TanStack Start + Better Auth + ZenStack + shadcn/ui integration.

The request wording is "为所有组件进行升级". The agreed surfaces are:

- npm dependencies and devDependencies in `package.json` / `pnpm-lock.yaml`
- shadcn/ui primitive source copies under `src/components/ui/*`
- Better Auth UI application source copies under `src/components/{auth,settings,user}/*` only after registry diff proves the current upstream is still compatible with this repo
- generated integration artifacts that may need regeneration after dependency upgrades

Better Auth UI email registry templates under `src/components/email/*` are not part of the default refresh. They remain vendor-like source copies and are refreshed only if dependency upgrades produce a compile/runtime failure that requires syncing them.

Uninstalled shadcn components are not added as part of this upgrade.

## Requirements

- Use `pnpm` only.
- Keep generated outputs read-only unless regenerated by project scripts:
  - `src/routeTree.gen.ts`
  - `zenstack/{schema,models,input}.ts`
  - `zenstack/_better-auth.zmodel`
  - `src/paraglide/*`
- Preserve project architecture:
  - TanStack Start route organization and server function boundaries
  - Better Auth owns identity and auth tables
  - ZenStack policy owns business data authorization
  - shadcn/ui primitives remain in `src/components/ui/*`
- Treat Better Auth / Better Auth UI upgrades as schema-sensitive:
  - rerun `pnpm ba:shadow` when BA schema or plugin surface changes
  - verify generated shadow schema diff
- Treat ZenStack / Prisma upgrades as database-sensitive:
  - regenerate ZenStack artifacts
  - do not hand-edit generated ORM output
- Treat TanStack / Vite / React / TypeScript upgrades as app-wide:
  - verify type-check, tests, build, and route generation behavior
- Treat shadcn/ui and selected Better Auth UI registry refreshes as source-copy updates:
  - expected to overwrite vendor-like files
  - preserve intentional project integration edits, especially `#/*` imports and localization factories
- Exclude `src/components/email/*` from routine registry refresh:
  - these files are BA UI email templates
  - `email-styles.tsx` is semi-vendor and may reset inline defaults when refreshed
  - refresh only when validation proves the dependency upgrade requires it
- Exclude uninstalled shadcn primitives from routine refresh:
  - do not use `shadcn add --all --overwrite`
  - update only the components currently listed by `shadcn info` as Installed Components
- Treat BA UI app registry refresh as high-risk:
  - current dry-run creates `src/@components/auth/*` instead of updating `src/components/auth/*`
  - current dry-run adds `@base-ui/react`, which conflicts with the repo's `radix-vega` foundation
  - do not apply BA UI registry overwrites directly in the real tree
- Treat deprecated `@react-email/components` as an upstream Better Auth UI peer dependency:
  - `@better-auth-ui/react` declares `@react-email/components >=1.0.12` as a peer dependency in both the installed `1.6.3` package and current `1.6.18` metadata
  - do not remove it while `@better-auth-ui/react` still requires that peer
  - record the deprecation as an upstream BA UI constraint rather than a local package drift
  - keep local email-template import migration optional and separate from the all-components upgrade
- Treat Better Auth shadow generation as a risk area:
  - current `pnpm ba:shadow` fails when PostgreSQL is not reachable because `src/lib/auth/config.ts` imports `#/lib/db`, whose module load runs `await db.$connect()`
  - current `ba:shadow` script uses `npx @better-auth/cli@latest`; npm metadata shows `@better-auth/cli@latest` is `1.4.21`, while `better-auth` latest is `1.6.x`
  - the CLI must be upgraded to its newest available stable version explicitly and validated against the upgraded Better Auth runtime
  - implementation must verify whether BA shadow generation still works after upgrading Better Auth and must not assume CLI/runtime versions are aligned

## Acceptance Criteria

- [ ] The upgrade scope is explicitly chosen before implementation.
- [ ] `package.json` and `pnpm-lock.yaml` reflect the chosen dependency upgrade policy.
- [ ] Installed packages resolve without pnpm warnings about ignored project settings.
- [ ] shadcn/ui source-copy updates, when included, are applied only to intended primitive/vendor-copy files.
- [ ] BA UI email templates are unchanged unless a failing validation requires refreshing them.
- [ ] No currently uninstalled shadcn primitive is added just because `--all` would include it.
- [ ] BA UI app registry refresh is either skipped with documented compatibility reasons or applied through a reviewed staging diff, not direct overwrite.
- [ ] The `@react-email/components` deprecation is classified with its dependency owner.
- [ ] If `@react-email/components` remains, the final summary explains that it is required by `@better-auth-ui/react` peer dependency.
- [ ] Better Auth shadow schema is regenerated or explicitly proven unchanged when Better Auth-related packages change.
- [ ] Better Auth shadow generation either works with the upgraded stack or the blocker is fixed/documented before implementation is called complete.
- [ ] ZenStack generated artifacts are regenerated or explicitly proven unchanged when ZenStack / Prisma-related packages change.
- [ ] Paraglide and TanStack route generation remain healthy through the normal build/dev tooling path.
- [ ] Validation passes:
  - `rtk pnpm check`
  - `rtk pnpm test`
  - `rtk pnpm exec tsc --noEmit`
  - `rtk pnpm build`
- [ ] Any validation requiring `.env.local` is run only with local env and no secrets are committed.
